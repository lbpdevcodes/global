# M0 spike results (2026-10-27)

## 1. Reader framework: React Router in JavaScript with a client-only globe

- **Result: works.** React Router is now at **v8** (8.5.1), not the v7 the plan assumed.
  Framework mode with `ssr: false` and `prerender` builds from plain `.jsx`. It writes
  `index.html` plus `__spa-fallback.html`, and globe.gl, loaded in `useEffect`, never runs at
  build time.
- **Gotcha:** Cloudflare Pages turns a `_redirects` rewrite that targets
  `/__spa-fallback.html` into a 308 redirect to `/__spa-fallback`. That URL matches no route,
  so the page rendered React Router's 404. The fix is to target `/__spa-fallback`. The e2e
  `e2e/shell.spec.js` now asserts that the deep-link URL stays `/country/FRA`.
- **Verified by** Playwright against `wrangler pages dev`, Cloudflare's local Pages runtime.

## 2. SQLite kept in object storage between runs

- `backend/bin/with-stored-database`:
  1. Fetches the database.
  2. Runs the command.
  3. On success only, uploads a consistent copy (`VACUUM INTO`) and a dated backup.
- If the fetch fails, the script refuses to start unless `ALLOW_EMPTY_DATABASE=1`. Otherwise a
  credentials failure would upload an empty database over the history.
- **Verified** by `spec/bin/with_stored_database_spec.rb` (6 examples), using a local-directory
  store. A failed run exits with the command's status and leaves the stored file byte-identical.
  The command never sees the storage keys.
- **`s3://` branch verified 2026-10-28** against Linode Object Storage (`us-mia-1`), in a scratch
  folder deleted afterwards. All of these behaved as specified: refusing an empty store, the
  first run, fetching on the next, a failed run leaving the stored copy and backups unchanged,
  and the command seeing no keys. `aws s3 sync` up and back, the call the workflows rely on,
  also worked. A path on the endpoint (as wynston's `/synaptical/prod`) would break those
  listings, so the folder lives in `STORAGE_URL` instead.
- **Production boot needs a secret.** With no `config/master.key`, `RAILS_ENV=production`
  fails with "Missing `secret_key_base`". The daily workflow (M2) must provide
  `RAILS_MASTER_KEY` or `SECRET_KEY_BASE` as a GitHub secret.

## 4. Source findings that change the plan

- **REST Countries v3.1 is deprecated.** It now returns an error pointing to v5, which requires
  an API key. Decision: **use v5**. The key is in `backend/config/credentials.yml.enc` under
  `rest_countries.api_key`, and calls go through HTTParty.
  - **Paging:** `GET https://api.restcountries.com/countries/v5` returns 254 countries over
    3 pages (`limit` is at most 100 on the free plan), with `data.meta.more` set while more
    remain. Fields are selected with `response_fields`. The documented rate limit is 20 requests
    per 10 seconds; the monthly quota is not published.
  - **Encoding:** the response is `application/json` with no charset, and HTTParty returns the
    body as ASCII-8BIT. Force it to UTF-8 before writing or comparing it.
  - **Coverage:** `classification.un_member` matches our curated 193 exactly, and
    `un_observer` is PSE and VAT. Kosovo is **`UNK`** (alpha-2 `XK`), so it needs the code map.
  - **Capitals:** `capitals[]` can hold several entries (BOL, ZAF, SWZ, PSE). Use the one whose
    `attributes.primary` is true.
  - **Territories:** `classification.dependency_type` gives each territory's type but not its
    parent. Parents come from the curated seed list.
- **Wikidata UN membership is not a reliable seed.** The query returns 203 items, including 10
  historical states, and Denmark's membership sits on a realm item with no ISO code. The entity
  list is curated (ADR 0003).
- **Natural Earth's latest release is from May 2022** (ADR 0004 open item).
